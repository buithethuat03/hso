Chương 08: Báo Cáo Điểm Nghẽn, Bảo Mật & Lộ Trình Nâng Cấp

Tổng hợp phân tích chuyên sâu về các điểm nghẽn hiệu năng (Bottlenecks), các nguy cơ bảo mật/dupe vật phẩm tiềm ẩn và bản thiết kế lộ trình nâng cấp hiện đại hóa toàn diện Server HSO.

1. Phân Tích Điểm Nghẽn Hiệu Năng (Performance Bottlenecks)

1. Điểm Nghẽn Đồng Bộ Khóa (Lock Contention)

Hiện tại server dùng synchronized (map) bao trùm nhiều khối code tính toán sát thương và duyệt mảng người chơi dài. Khi 1 map có 100+ người cùng đánh quái, luồng xử lý sẽ bị xếp hàng chờ, gây hiện tượng trễ phím (Input Lag).

Khuyến nghị: Tách riêng tính toán damage ra khỏi synchronized block.

2. Quản Lý Kết Nối Database (Database Pipeline)

Hệ thống dùng kết nối JDBC cơ bản và nhiều lệnh ghép chuỗi SQL trực tiếp. Chưa có Connection Pool chuẩn doanh nghiệp (như HikariCP).

Khuyến nghị: Tích hợp HikariCP + PreparedStatement 100%.

3. Áp Lực Bộ Nhớ & Garbage Collection (GC Pressure)

Trong các hàm combat và nhặt đồ, các đối tượng ArrayList<Option> và Message được tạo mới liên tục hàng nghìn lần mỗi giây.

Khuyến nghị: Áp dụng Message Object Pooling / Netty ByteBuf.

4. Tái Cấu Trúc MenuController (>4000 Lines)

File MenuController.java quá lớn và xử lý theo mô hình switch-case nguyên khối, rất khó bảo trì và dễ sinh lỗi chéo khi thêm NPC mới.

Khuyến nghị: Chuyển sang mô hình Command Pattern / Dialog Tree Node.

2. Phòng Chống Dupe & Tấn Công Gói Tin (Exploit Prevention)

Nguy Cơ Tiềm Ẩn Vị Trí Rủi Ro Giải Pháp Kỹ Thuật Đã & Cần Triển Khai
Spam Packet Skill / Hack Cooldown MapService.java Đã có cơ chế đếm số lần vượt Cooldown: if (++conn.p.enough_time_disconnect > 5) conn.close(); ➔ Cần duy trì và giám sát thêm timestamp client.
Index Ngoài Biên (Out Of Bounds) Gói tin mảng do Client gửi Áp dụng hàm chặn an toàn Util.validIndex(idx, len) trên tất cả các handler đọc chỉ số túi đồ, kỹ năng, rương giữ đồ.
Dupe Vàng / Item Khi Giao Dịch Trade / Player_store Sử dụng cơ chế khóa 2 bước (Two-Phase Lock) và ghi log giao dịch chi tiết vào bảng log_trade để truy vết.
SQL Injection Nhập text từ Client Chuyển đổi toàn bộ các câu lệnh Statement.executeQuery sang PreparedStatement với tham số hóa (Parameterized queries).

3. Lộ Trình Nâng Cấp Đề Xuất (Future Architecture Roadmap)

🚀 4 Giai Đoạn Nâng Cấp Toàn Diện Server HSO
  1. Giai Đoạn 1: Tối Ưu Hóa Hạ Tầng & CSDL:
    • Nâng cấp MySQL Connection Pool với HikariCP (Pool size 20-30 connections).
    • Chuyển toàn bộ chuỗi SQL sang PreparedStatement.
  2. Giai Đoạn 2: Tái Cấu Trúc Menu & Tính Năng:
    • Tách MenuController.java thành các class Handler nhỏ theo từng NPC: BlacksmithMenuHandler, ElderMenuHandler, ArenaMenuHandler...
    • Hỗ trợ Hot-Reload cấu hình sự kiện và tỉ lệ rơi đồ bằng file JSON/YAML mà không cần tắt Server.
  3. Giai Đoạn 3: Nâng Cấp Mạng Sang Netty Engine:
    • Thay thế Socket blocking I/O truyền thống bằng Netty 4.x (Non-blocking I/O), giúp server chịu tải từ 5.000 đến 10.000 người chơi đồng thời trên 1 máy chủ VPS thông thường.
  4. Giai Đoạn 4: Mở Rộng Tính Năng Đỉnh Cao:
    • Chiến Trường Liên Server (Cross-Server Arena): Sử dụng Redis Pub/Sub để đồng bộ trạng thái chiến đấu giữa nhiều cụm server.
    • Hệ thống Đấu Giá Toàn Server (Global Auction House) với bảng thông báo thời gian thực.
